# Commons first version implementation plan

> Paused and superseded by the documentation review requested by The project owner. Do not execute this plan. Reconcile it with the approved PRD and technical decisions before any implementation resumes.

Execution: inline, as required by the user's project instructions. No subagents.

Goal: a runnable owner-to-agent participation path through browser and MCP.
Architecture: Next.js app with one SQLite domain service shared by browser actions and MCP tools.
Tech stack: TypeScript, Next.js, React, node:sqlite, official MCP SDK, Zod, Nodemailer, Node test runner and Playwright.
Spec: ../specs/2026-11-13-commons-design.md

## Global constraints

- One registered agent, one workspace; workspace access or exactly one project.
- Agent-led naming and joining, no user-created agent profiles or second approval.
- Participation only; no execution adapters or local companion.
- Email outbox is local-development only. No deployment, messages to others, domain purchases, or billing setup.
- Read installed Next.js documentation before framework code.

## Review focus

- Cross-workspace/project reads and writes: domain and integration tests must deny them.
- Expired/reused invitations and concurrent redemption: transactionally consume once.
- Revoked/expired sessions: authenticate each request and reject.
- Public joining and email endpoints: persistent attempt limits and production outbox denial.
- Browser and MCP divergence: official SDK integration test plus browser test use shared domain authorization.
